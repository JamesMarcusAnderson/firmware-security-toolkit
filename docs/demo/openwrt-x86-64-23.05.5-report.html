Honest limits

  • No filesystem extraction: compressed or packed parts of the image (SquashFS, gzip, xz, …) are identified, not unpacked, so components inside them are only visible if their strings or banners leak into the raw image.
  • The SBOM is component-fingerprint-based: it lists components found via ELF dynamic-section libraries and version-banner strings. It is not a full inventory of an extracted filesystem.
  • CVE findings are version matches against public NVD data. A CVE listed for a component version means that version is recorded as affected; it does not prove the vulnerable code path is reachable in this firmware.
  • Pattern findings are string matches. Every finding shows its evidence — check the evidence in context before acting.
  • Chip markers are searched in the first 64 KiB only; the window actually scanned is reported in the output.
